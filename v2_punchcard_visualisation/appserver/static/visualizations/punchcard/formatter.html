Categorical mode — colors each distinct value of the 4th "by" field with its own solid color. Leave Category colors blank to use Splunk's default categorical palette.
Threshold mode — colors the count metric itself by numeric boundary; no separate color field needed. A value equal to a boundary falls into the bucket above it (e.g. with boundaries 10,20 a value of 20 gets the 3rd color, not the 2nd). Example: boundaries 10,20 with colors 65778A,D41F1F,118832 gives count<10 → 65778A, 10≤count<20 → D41F1F, count≥20 → 118832.
Field value mode — no settings here. The 4th "by" field's own value is used directly as each circle's CSS color, computed however you like in SPL, e.g.: stats count by x y | eval colour=case(count<10,"65778A", count<=20,"D41F1F",count>20,"118832") | table x y count colour. Accepts any valid CSS color (hex, rgb(), hsl(), named colors); blank values fall back to the default blue. Hex codes work with or without a leading #.
Sequential mode — interpolates a smooth gradient between Min color and Max color across Number of bins, driven by a numeric 4th "by" field (a separate field from the count metric).
